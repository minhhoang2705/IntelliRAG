# Load Testing Framework - Usage Examples

Quick reference guide for common testing scenarios.

## Complete Test Suite

Run the entire Day 2 load testing suite:

```bash
cd tests/load
./run-all-tests.sh
```

**What it does:**
- Pre-flight checks for tools and endpoints
- vLLM tests: baseline, stress, breaking point
- Embedding tests: standard, batch optimization, breaking point
- E2E RAG tests: 50, 100, 200 concurrent users
- Generates markdown reports
- Total duration: ~2-3 hours

## Quick Testing (Skip Breaking Points)

For faster testing during development:

```bash
./run-all-tests.sh --skip-breaking
```

**Duration**: ~45 minutes

## Custom Test Scenarios

### vLLM - Custom Baseline Test

```bash
cd scripts

# Custom parameters
./run-hey-test.sh \
  --endpoint https://llm.blockchainradar.xyz/v1/chat/completions \
  --data '{"model":"Qwen/Qwen3-0.6B","messages":[{"role":"user","content":"Test"}],"max_tokens":50}' \
  --concurrent 75 \
  --requests 1500 \
  --test-name vllm-custom-baseline
```

### Embedding - Test Specific Batch Size

```bash
# Test with 15 texts per batch
./run-hey-test.sh \
  --endpoint https://embed.blockchainradar.xyz/vectorize \
  --data '{"texts":["t1","t2","t3","t4","t5","t6","t7","t8","t9","t10","t11","t12","t13","t14","t15"],"normalize":true}' \
  --concurrent 50 \
  --requests 1000 \
  --test-name embedding-batch-15
```

### Locust - Custom User Profile

```bash
cd locust

# Use power users only
locust -f locustfile.py \
  --user-classes PowerUser \
  --headless \
  --users 30 \
  --spawn-rate 5 \
  --run-time 10m \
  --host http://localhost:8000

# Use burst pattern
locust -f locustfile.py \
  --user-classes BurstUser \
  --headless \
  --users 100 \
  --spawn-rate 50 \
  --run-time 5m
```

## Monitoring During Tests

### GPU Monitoring (vLLM tests)

```bash
# In separate terminal during vLLM tests
watch -n 1 nvidia-smi

# Or with detailed metrics
nvidia-smi --query-gpu=utilization.gpu,memory.used,memory.total,temperature.gpu --format=csv -l 1
```

### CPU Monitoring (Embedding tests)

```bash
# Watch embedding pod resources
watch -n 2 'kubectl top pods -n kserve'

# Detailed pod metrics
kubectl top pods -n kserve -l serving.kserve.io/inferenceservice=embedding-service
```

### GKE App Monitoring (E2E tests)

```bash
# Watch HPA status
watch -n 5 'kubectl get hpa -n app'

# Pod resource usage
watch -n 3 'kubectl top pods -n app'

# View logs
kubectl logs -n app -l app.kubernetes.io/name=intellirag-app --tail=50 -f
```

## Analyzing Results

### Check Success Rates

```bash
# vLLM results
grep -h "Status code\|Success rate" results/vllm/*.txt

# Embedding results
grep -h "Status code\|Success rate" results/embedding/*.txt
```

### Extract Latency Metrics

```bash
# vLLM P95 latencies
grep "95% in" results/vllm/*.txt

# Embedding P95 latencies
grep "95% in" results/embedding/*.txt
```

### Find Breaking Point

```bash
# Check breaking point tests for errors
grep -l "Error distribution" results/vllm/vllm-breaking-*.txt
grep -l "Error distribution" results/embedding/embedding-breaking-*.txt
```

## Troubleshooting Scenarios

### vLLM Endpoint Down

```bash
# Check CloudFlare Tunnel
sudo systemctl status cloudflared

# Restart tunnel if needed
sudo systemctl restart cloudflared

# Verify endpoint
curl https://llm.blockchainradar.xyz/health
```

### Port-Forward Issues

```bash
# Kill existing port-forwards
pkill -f "port-forward.*intellirag-app"

# Start fresh
kubectl port-forward -n app svc/intellirag-app 8000:8000 &

# Test
curl http://localhost:8000/ready
```

### Test Hangs or Times Out

```bash
# Check if services are responding
curl -v https://llm.blockchainradar.xyz/health
curl -v https://embed.blockchainradar.xyz/health

# Check GKE pod status
kubectl get pods -n app
kubectl get pods -n kserve

# View logs
kubectl logs -n app deployment/intellirag-app --tail=100
```

## Best Practices

### Before Testing

1. **Verify Services**: Check all endpoints are healthy
2. **Clear Previous Results**: Archive or delete old test results
3. **Monitor Resources**: Have monitoring dashboards ready
4. **Check Time**: E2E tests run for 13+ minutes

### During Testing

1. **Watch for Errors**: Monitor test output for failures
2. **Check Resources**: Verify GPU/CPU utilization
3. **Note Anomalies**: Record any unexpected behavior
4. **Don't Interrupt**: Let breaking point tests complete

### After Testing

1. **Review Reports**: Analyze generated markdown reports
2. **Check Metrics**: Review Locust HTML reports
3. **Compare Baselines**: Compare against Day 1 results
4. **Document Findings**: Update Day 2 capacity analysis
5. **Archive Results**: Save results with timestamp

## Integration with Day 3 Optimization

Use test results to inform optimizations:

```bash
# After reviewing Day 2 results, update configurations:

# 1. GPU memory optimization
kubectl edit -n kserve inferenceservice vllm-qwen
# Update: --gpu-memory-utilization=0.90

# 2. Deploy embedding HPA
kubectl apply -f kubernetes/kserve/embedding-service-hpa.yaml

# 3. Fix GKE memory requests
helm upgrade intellirag-app ... --set resources.requests.memory=1200Mi

# 4. Re-run tests to validate
./run-all-tests.sh
```
